## Aegis 2FA v1.1.2

Web 版の同期エラー（`http_400 revision_must_advance`）を直し、パスキーの登録名を端末間で共有できるようにし、
アプリ内の**プライバシーポリシー（`/privacy`）**を追加しました。Android アプリは、Web 版が同期する
パスキー一覧を消さずに保持します。PHP（Xserver 用）ZIP と Android APK をまとめて配布します。

### 同期（不具合修正）

- **Web 版で「同期する」を押すと `http_400 revision_must_advance` になっていた不具合を修正**。
  ローカルに未送信の変更が無い（`envelope.revision <= 最後に同期した revision`）ときも `PUT` を
  送っていたため、PHP 版の `$nextRevision <= $baseRevision` の検査で拒否されていました。
  いまは未変更なら `GET` して取りに行きます。別端末でサーバーの revision が進んだ状態でも
  先に取り込んでから送るので、古いローカル版で上書きしません。
- **取り込みの判定を厳密に**。取得開始時の基準 revision と封筒の同一性で比べ、
  サーバーが「最後に一致した revision」より古いときだけ巻き戻りとして送り返します。
  復号中にローカルが編集された・ロックされた・ボルトを切り替えた場合は、その取り込みを捨てて
  次の同期に任せます（古いマージ結果で編集や削除記録を上書きしない）。
- **待機中にロックされたら平文は戻さない**（封筒と同期状態だけ反映）。
- **マスターパスワード変更との競合**。封筒の鍵ラップ（`kdf.salt` / `wrappedKey`）が食い違うときは
  自動で取り込まず、競合として提示します（取り込むとパスワード変更が取り消され、
  古いパスワードが有効に戻ってしまうため）。`PUT` が `409` のときだけ 3 択の競合解決を出します。
- サーバーにボルトが無い（404）ときは base 0 で作り直します。作り直しの間にボルトの世代が
  変わっていたら、古い ID では送りません。
- ロック中に未送信の変更とサーバーの更新が重なったときは、捨てずに競合として提示します。
- エラー本文の `error`（`revision_must_advance` / `invalid_body` / `not_found` …）を読んで、
  画面には日本語のメッセージを出します（生の `http_400` は設定の「詳細」にだけ表示）。

### パスキーの登録名を端末間で共有

- `VaultData.passkeyInfos`（`id` / `name` / `createdAt` / `deviceId` / `deviceName` / `deletedAt`）だけを
  暗号化ボルトの中で同期します。`wrappedDek`・PRF salt・credential の秘密は従来どおり端末の
  IndexedDB のみに置き、外には出しません。
- `mergePasskeyInfos()` で統合（名前は新しい `createdAt`、削除の印は取り消さない）。
  登録日時が同じ（端末名の付け替え）なら端末名で決め、両端末で同じ結果になります。
- 設定画面は「この端末で解除に使えるパスキー」と「ほかの端末で登録されたパスキー
  （この端末では登録が必要）」を分けて表示します。

### Android（互換対応）

- `passkeyInfos` を読み書き・マージで保持するようにしました。Web 版が入れた一覧を
  Android の push が消しません。未知のキーを読み飛ばす挙動は維持しています（古いアプリ・新しいアプリの
  どちらでも封筒を読める形のまま）。
- `versionCode` 4 / `versionName` 1.1.2。署名鍵は v1.1.1 と同じ配布鍵なので、上書き更新できます。

### プライバシーポリシー（新規）

- アプリ内の `/privacy`（日本語・英語）とリポジトリの `PRIVACY.md`。
- ボルト未作成・ロック中・解錠中のどこからでも直リンクで開けます。リンクはフッター、設定の
  「このアプリについて」、ロック画面、ボルト作成画面、同期画面に置いています。
- Xserver の `/aegis/privacy` も `.htaccess` の SPA フォールバックで開けます（テストで実測）。

### PHP（Xserver 用）

- `aegis-php-xserver-v1.1.2.zip` は中に `aegis/` フォルダを含みます。`public_html/` で展開すると
  `public_html/aegis/` になり、そのまま動きます（Composer / Node 不要）。
- バージョンは `1.1.2`（`/api/health` も返します）。
- **既存環境の更新**: 展開すると `.htaccess` も配布版で置き換わります。`.htaccess` の `SetEnv` で
  設定を渡している環境（`AEGIS_CONFIG` や `AEGIS_DB_PATH` など）は、展開前に既存の `.htaccess` を
  退避し、展開後にその `SetEnv` 行をすべて配布版の `.htaccess` へ戻してください。
  これらを使っていない環境では、この手順は不要です（既定の場所に DB を作ります）。
- **DB の保存先**: 既定では `DOCUMENT_ROOT` の 1 つ上（例: `public_html` の隣）に `aegis-data/` を
  作り、そこに `aegis.db` を置きます。PHP の実行ユーザーがその場所に作れないと API は
  「データベースの保存先を確保できません」で止まります。その場合は `aegis-config.php` の
  `db_path` に、書き込みできる**公開領域外**の絶対パスを指定してください
  （詳しくは `deploy/xserver/README.md` の「設定」）。
